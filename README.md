Usar SELECT * está bien cuando recién estás explorando una tabla y querés ver todas sus columnas, pero no es una buena práctica en producción. El principal problema es el rendimiento, porque la base de datos trae todas las columnas aunque solo necesites algunas. Por ejemplo, si la tabla sales tiene 9 columnas y solo necesitás 3, igual se leen y se envían las 9, lo que hace que la consulta consuma más tiempo y recursos, especialmente cuando la tabla tiene miles o millones de registros. Además, al pedir todas las columnas, la base de datos no puede aprovechar algunas optimizaciones que la harían más rápida. Otro problema es el mantenimiento: si alguien agrega una nueva columna a la tabla, todas las consultas que usan SELECT * la incluirán automáticamente, lo que puede afectar reportes o aplicaciones que esperaban una estructura diferente. Por eso, en producción es recomendable seleccionar únicamente las columnas que realmente se necesitan.
¿Por qué son importantes los alias para un stakeholder no técnico? Los nombres de las columnas de una base de datos están pensados para quien la programa, no para quien lee el reporte. Suelen estar en inglés, abreviados y sin espacios, porque así lo requiere la sintaxis de SQL, ero la persona del área de finanzas que recibe el resultado no conoce esas convenciones y no tiene por qué conocerlas.
El caso concreto de total_amount, cuando el equipo de finanzas abre un reporte y ve una columna llamada total_amount, tiene que resolver varias ambigüedades antes de poder usar el dato:
¿"total" de qué? ¿El total de esa línea de venta, o el total acumulado del pedido completo?
¿"amount" en qué unidad? ¿Son pesos, dólares, unidades vendidas?
¿Incluye impuestos? ¿Incluye descuentos? Ninguna de esas preguntas se responde mirando la columna. Se responden preguntándole al área de datos  lo que genera un ida y vuelta que consume tiempo de las dos partes, y que se repite con cada persona nueva que abre el reporte. Con un alias, el dato se explica solo evitando asi reuniones, documentación adicional, ni que el stakeholder aprenda inglés técnico. Es una línea de código que elimina una consulta recurrente.
